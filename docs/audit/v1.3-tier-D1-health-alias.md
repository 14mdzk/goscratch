# v1.3 Tier D1 — Remove Deprecated `GET /health` Alias

**Branch:** `fix/d1-remove-health-alias`
**Roadmap reference:** Tier D, row D1 (remove deprecated `GET /health`
alias, announced in the v1.2 CHANGELOG).

## Design (decided)

Removal, not redirect: the alias was deprecated exactly so callers would
move. A 301 keeps the dead path working and the drift gate / spec /
proxy surface carrying it. Deleted surface:

- Route: `internal/module/health/module.go` (`router.Get("/health", …)`
  + back-compat comments). `LivenessCheck` handler stays (serves
  `/healthz/live`).
- Spec: `/health` path block in `internal/module/docs/openapi.yaml`
  (drift gate fails otherwise).
- Edge: `deploy/nginx/nginx.conf` `location /health` → `/healthz/live`
  (same proxy, still un-rate-limited); prod healthchecks in
  `deploy/docker/docker-compose.prod.yml` (2×) → `/healthz/live`.
- Docs: `README.md`, `docs/QUICKSTART.md` (2×) → `/healthz/live`.
- Tests pin the removal, not just the absence:
  - `handler_test.go` `TestHealthAliasLiveness` → `TestHealthAliasRemoved`
    (404 on the unit app).
  - `integration_test.go` alias subtest → asserts 404; the adjacent
    `/healthz/live` 200 subtest already covers the canonical path.
  - `cmd/openapi-drift/drift_test.go`: drop `"GET /health"` from the
    expected-routes fixture (the generic `{"/health", false}`
    isExcluded case stays — it tests exclusion logic, not this route).
