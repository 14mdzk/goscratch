# v1.3 Tier B Execution (1/3) — Fold + Delete Retired Spec (Health Pilot)

**Branch:** `docs/b-fold-retired-spec`
**Roadmap reference:** ADR-011 consequences §(1) (fold + delete
`docs/openapi.yaml` with the health pilot). Supersedes Tier B rows
B2–B4 as written.

## Design (decided)

The retired `docs/openapi.yaml` (58 KB, referenced by no code — verified
by grep over `*.go`, `Makefile`, `*.sh`, `*.yml`, live `*.md`) is deleted
after folding its unique health content into the canonical
`internal/module/docs/openapi.yaml` (embedded, served, drift-gated):

- `/healthz/ready`: full description (parallel sub-checks, shared
  deadline + `HEALTH_READINESS_TIMEOUT_SEC`, noop self-pass, k8s target)
  plus the `503` response the canonical spec was missing. The 503 is
  real: `ReadinessCheck` returns `StatusServiceUnavailable` with status
  `degraded` when any checker fails (verified in handler.go).
- `/healthz/live`: always-200 / no-dependency / k8s-target description.
- `HealthCheckResponse.status` enum corrected to `[ready, alive,
  degraded]` — the old `[ok, ready, alive]` omitted the real 503 value
  and included `ok`, which is only ever a per-*check* value, never the
  top-level status (verified emitters in handler.go).
- The retired copy's `/health` alias block dies with the file (alias
  removed in D1 anyway).

Remaining references to the filename are historical audit prose
(describing past PRs) and the ADR itself — intentionally untouched.
