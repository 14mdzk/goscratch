# v1.3 Tiers C3 + C4 — GeoJSON Marshaling + geoutil Haversine

**Branch:** `feat/c3-c4-geojson-geoutil`
**Roadmap reference:** Tier C rows C3 (GeoJSON `MarshalJSON`/`UnmarshalJSON`
on `geo.Point`, `geo.Polygon`, RFC 7946) and C4 (`pkg/geoutil` pure-Go
helpers: `Haversine`, `BoundingBox.Contains`).

## Design (decided)

### C3 — GeoJSON on the value types

- `point_geojson.go`: `Point.MarshalJSON` emits
  `{"type":"Point","coordinates":[lon,lat]}` (Lon-first, RFC 7946 §3.1.2,
  no altitude). `UnmarshalJSON` requires `type == "Point"`, exactly
  2 numeric coordinates, then range-validates through `NewPoint`
  (out-of-range → `ErrInvalidLongitude`/`ErrInvalidLatitude`, never a
  silently-wrapped literal).
- `polygon_geojson.go`: `Polygon.MarshalJSON` emits
  `{"type":"Polygon","coordinates":[[[lon,lat],...],...]}` (exterior
  first, then holes, RFC 7946 §3.1.6). `UnmarshalJSON` requires
  `type == "Polygon"`, ≥ 1 ring, each ring decoded to `[]Point`, then
  validated through `NewPolygon` (closure + count rules stay in one
  place). Empty-rings input (`"coordinates":[]`) is rejected:
  a Polygon with no rings carries no shape.
- Unknown `type` values and malformed shapes return descriptive
  `*json.SyntaxError`-compatible errors via `fmt.Errorf` with the
  package's `ErrInvalidGeoJSON` sentinel (new in `errors.go`) so callers
  can `errors.Is`.
- Round-trip property tests: table-driven marshal→unmarshal→marshal
  stability plus golden strings for one Point and one Polygon.

### C4 — `pkg/geoutil`

- `Haversine(a, b geo.Point) geo.Distance`: great-circle distance on a
  spherical earth, `atan2` formulation (stable for antipodal and
  near-identical points), IUGG mean radius `6371000 m` (named constant,
  documented). Returns `geo.Distance` via `NewDistance` (Haversine output
  is ≥ 0 by construction, so no new error path).
- `(BoundingBox).Contains` already exists as a `geo` method (shipped in
  C1); C4 does NOT duplicate it — the row's parenthetical predates C1.
  No point-in-polygon (not in the C4 row; polygon.go explicitly defers it).
- Tests: table-driven with independent oracles — same point → exactly 0;
  1° of equator ≈ 111,195 m (±0.5%); NYC–London ≈ 5,570 km (±0.5%);
  antipodes ≈ πR (±1e-6 relative); symmetry `H(a,b)==H(b,a)`; pole to pole.
- Package has no external dependencies (stdlib only), mirroring `geo`.

## Out of scope

- 3D coordinates / altitude (RFC 7946 allows, row does not ask).
- `bbox` / `Feature` / `FeatureCollection` marshaling (no row asks).
- Point-in-polygon, ST_DWithin wrappers (explicitly deferred).
- pgx/GeoJSON interplay (orthogonal; C2 covers EWKB).
