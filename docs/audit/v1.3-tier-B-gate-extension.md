## Design (decided)

- `validateSpecDocument` in `cmd/openapi-drift/main.go`: loads the spec
  bytes through `openapi3.NewLoader().LoadFromData` and runs
  `doc.Validate(loader.Context)` — valid OpenAPI 3.0.x, every `$ref`
  resolves, operations complete. Runs before the route diff; failure
  exits 1 with an `invalid spec` message under the same gate semantics.
- Same binary, same `make openapi-drift` / `make lint` target, same CI
  step — no workflow change.
- The server gains no runtime dependency: the import lives only in the
  `cmd/openapi-drift` tool package (separate main package).
- Tests: `TestValidateSpecDocument_RealSpec` (canonical spec must pass),
  fixture table (dangling `$ref`, missing version, non-OpenAPI doc,
  operation without responses), nonexistent path. Fixture versions are
  quoted (`version: "1"`): unquoted `1` trips the loader's string-type
  check before reaching the intended failure — found live, fixed.
- `go mod tidy` applied; kin-openapi is now a direct dependency.
- govulncheck: exit 0 ("affected by 0"). The two verbose findings
  (GO-2026-4950, GO-2026-5932) are in pre-existing `fasthttp`, uncalled
  by this tool — not introduced here.
