# v1.3 Tier B Execution (3/3) — Per-Module Spec Reconciliation (Auth + Storage)

**Branch:** `docs/b-reconcile-auth-storage`
**Roadmap reference:** ADR-011 consequences §(2) (per-module reconciliation
PRs, reviewed conformance). First installment: auth + storage + shared
components. Users/roles/SSE/job/audit/health blocks verified conformant
(route tables match; handler shapes match spec envelopes).

## Findings (all verified against handler/middleware code)

1. `POST /auth/login`, `POST /auth/refresh`: missing `429` (dedicated
   20 req/5 min/IP limiter, verified in `auth/module.go`) and `503`
   (fail-closed backend error → `RATE_LIMIT_ERROR`, verified in
   `rate_limit.go:64`). The retired spec documented both; the canonical
   spec lost them.
2. Same two 200s: missing `X-RateLimit-Limit/Remaining/Reset` response
   headers (emitted on every allowed request, verified in
   `rate_limit.go:71-73`). New `components/headers` definitions.
3. `POST /auth/logout`: missing `security: bearerAuth` + `401` (route is
   auth-gated; handler 401s without a callerID, verified), description
   gains the JWT note (retired-spec wording).
4. `TooManyRequests` example: `code: BAD_REQUEST` is wrong — the middleware
   emits `RATE_LIMIT_EXCEEDED` (verified in `rate_limit.go:76`).
5. `POST /files/upload`: missing `415` (content sniff allowlist, verified
   live with curl during F2: text/plain → 415). Oversize stays 400
   (verified: `BadRequestf`, no 413 path).
6. New `ServiceUnavailable` shared response (referenced by the restored
   503s).
7. `info.description`: global-limiter paragraph (100 req/min default;
   auth endpoints carry the tighter dedicated budget) so the per-op 429s
   read in context.
8. `ErrorResponse.code` enum completed: it omitted `UNSUPPORTED_MEDIA_TYPE`
   and the two rate-limiter codes (the new kin-openapi gate rejects examples
   with off-enum codes — caught live on this PR's CI). The limiter emitted
   both as raw strings; they are now `apperr.CodeRateLimitExceeded` /
   `CodeRateLimitError` (byte-identical values, registry stays exhaustive
   and the spec enum mirrors it).
